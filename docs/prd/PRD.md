# PRD v1.0

## PRD는 우리가 어떤 것을 만드는 것인지 정의 하고 이야기 하는 문서이다.

> **오늘 한 게 없다고? 무무는 봤는데.**
>
>
> 작은 하루가 별조각이 되고, 별친구가 그걸 기억하는 AI 루틴 서비스.
>

## 2. 제품 개요

## 2.1 제품명

**Polaris**

Polaris는 북극성처럼 사용자의 하루에 작은 방향을 제안하는 서비스다.

사용자가 직접 거창한 목표를 세우지 않아도, 캐릭터가 말을 걸고 AI가 작은 미션을 제안한다.

Polaris의 세계에서 사용자의 사소한 행동은 별조각이 된다.

```
물 한 컵 마시기
창문 3분 열기
현관까지 다녀오기
책상 위 물건 하나 치우기
오늘 하늘 색깔 떠올리기
```

이런 행동은 현실에서는 너무 작아 보일 수 있지만, Polaris 안에서는 캐릭터가 기억하는 하루의 증거가 된다.

---

## 2.2 제품 한 줄 정의

**Polaris는 사용자가 고른 별친구가 설문으로 사용자의 하루를 알아가고, AI가 그 맥락을 바탕으로 작은 미션을 하나씩 제안하며, 미션 완료·별조각·캐릭터 꾸미기·SNS 공유로 루틴을 지속하게 만드는 AI 다마고치형 루틴 서비스다.**

---

## 2.3 제품이 해결하려는 문제

현대 사회의 많은 사용자는 “외롭다”, “무기력하다”고 직접 말하지 않더라도 일상 속에서 다음 행동을 정하기 어려워한다.

```
오늘 뭘 해야 할지 모르겠다.
목표를 세우는 것부터 부담스럽다.
체크리스트 앱은 너무 딱딱하다.
루틴을 만들고 싶지만 혼자서는 오래 못 간다.
누군가 말을 걸어주면 좋겠지만 실제 관계는 부담스럽다.
작은 행동을 해도 별 의미가 없어 보인다.
```

Polaris는 이 문제를 아래 방식으로 해결한다.

```
캐릭터가 먼저 말을 건다.
설문으로 사용자의 생활 맥락을 가볍게 파악한다.
AI가 지금 할 수 있는 작은 미션을 하나 제안한다.
사용자가 미션을 거절하면 다음 미션을 제안한다.
사용자가 미션을 완료하면 캐릭터가 질문 1개를 던진다.
사용자가 답변하면 별조각을 지급한다.
별조각으로 스킨/소모품을 구매한다.
꾸민 캐릭터 카드를 SNS에 공유한다.
공유 링크와 알림을 통해 초기 재방문/확산 가능성을 검증한다.
```

## 2.4 제품 포지셔닝

Polaris는 자기계발 앱처럼 보이면 안 된다.

Polaris는 “해야 할 일 관리 도구”보다 “작은 일상을 같이 살아주는 캐릭터 앱”에 가깝다.

### 사용자에게 보이는 포지셔닝

```
귀여운 캐릭터가 오늘의 작은 미션을 제안해주는 앱
내 일상이 별조각이 되는 캐릭터 루틴 앱
AI가 나에게 맞는 루틴을 가볍게 골라주는 앱
내 캐릭터를 키우고 꾸미며 하루를 쌓는 앱
```

### 내부적으로 해결하는 문제

```
선택 피로
루틴 부재
현대적 외로움
관계 부담
작은 행동의 무가치감
재방문 동기 부족
```

### 피해야 할 표현

```
외로운 사람을 위한 서비스
무기력한 사람 치료 서비스
쉬었음 청년 전용 서비스
생활 교정 서비스
자기관리 실패자를 위한 앱
```

## 3. 브랜드 카피 / 마케팅 카피

## 3.1 카피 전략

Polaris의 카피는 “감성적이고 예쁜 말”만으로는 부족하다.

SNS에서 처음 봤을 때 멈추게 하는 짧은 훅이 필요하다.

마케팅 자료 조사에서 얻은 원칙은 다음이다.

```
1. 중요한 문장을 앞에 둔다.
2. 너무 긴 설명보다 짧고 바로 이해되는 문장이 유리하다.
3. 시각 자료와 카피가 함께 행동을 유도해야 한다.
4. 질문형/반전형/고백형 훅은 SNS 초반 주목에 유리하다.
5. 브랜드 목소리는 일관되어야 한다.
```

Polaris는 이를 기반으로 두 가지 톤을 병행한다.

| 톤 | 목적 | 사용 위치 |
| --- | --- | --- |
| X/밈형 카피 | 스크롤을 멈추게 하는 어그로/공유성 | SNS 카드, 랜딩 히어로, 배너 |
| 인스타 감성형 카피 | 브랜드의 따뜻한 세계관 전달 | 브로셔, 서비스 소개, 공유 이미지 |

### 최종 추천 X형 메인 카피

> **오늘 한 게 없다고? 무무는 봤는데.**
>

이 문장은 아래 장점이 있다.

```
사용자가 흔히 하는 자기평가를 뒤집는다.
캐릭터가 사용자의 작은 행동을 알아봤다는 감정을 준다.
무무의 말투와 세계관을 바로 보여준다.
밈처럼 짧고 공유하기 쉽다.
```

## 4. 핵심 흐름

## 4.1 최종 시스템 흐름

```
회원가입/로그인
→ 캐릭터 종류 선택
→ 캐릭터 이름 설정 및 생성
→ 캐릭터가 설문조사 형식으로 질문
→ 선택지 기반 초기 사용자 프로필 생성
→ AI가 캐릭터 말투로 첫 미션 제안
→ 사용자는 미션을 수행하거나 거절
→ 거절 시 다음 미션 제안
→ 미션 완료 클릭
→ 캐릭터가 미션 관련 질문 1개 제시
→ 사용자가 텍스트로 답변
→ 캐릭터가 완료 반응
→ 별조각 지급
→ 아이템 구매
→ 스킨 장착 또는 소모품 사용

선택한 캐릭터가 완료 질문을 한다.
선택한 캐릭터가 SNS 카드에 등장한다.
```

## 5.2 캐릭터 매력 설계 원칙

캐릭터는 “귀여움”만으로는 부족하다.

각 캐릭터는 아래 요소를 모두 가져야 한다.

```
하찮은 행동 패턴
짧고 기억나는 말투
알고 보면 사연 있는 서사
사용자의 작은 행동에 과하게 반응하는 태도
SNS 카드에 들어갔을 때 밈이 될 수 있는 문구
```

캐릭터의 감정 공식은 다음과 같다.

```
하찮은 외형
+ 이상한 말버릇
+ 작고 반복되는 욕구
+ 뒤늦게 밝혀지는 사연
+ 사용자의 루틴으로 조금씩 회복되는 관계
```

## 5.3 현재 캐릭터 3종

## 5.3.1 노바

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | 자기가 별이었다는 걸 까먹은 별알 |
| 성격 | 다정함, 조심스러움, 기억이 듬성듬성함 |
| 하찮은 포인트 | 자주 굴러다니고, 별조각을 먹을 수 있는 건 줄 안다 |
| 말투 | 짧고 느림. 문장 끝이 작게 흐려짐 |
| 대표 대사 | “오늘도… 있었네.” |
| 감정 키워드 | 방향, 기억, 작은 빛 |
| 사용자에게 주는 감정 | 안심, 다정함, 작은 성취감 |

### 서사

노바는 원래 밤하늘에서 길을 잃은 사람들에게 아주 작게 보이던 기준점이었다.

크게 빛나는 별은 아니었지만, 같은 자리에 오래 머무르는 별이었다.

하지만 사람들이 점점 작은 하루를 별것 아니라고 여기기 시작하면서 노바는 작아졌고, 결국 자기가 별이었다는 사실도 잊은 채 별알이 되었다.

노바는 사용자가 작은 미션을 해낼 때마다 “아, 이런 것도 빛이었지” 하고 조금씩 기억을 되찾는다.

### 소개 문구

```
노바는 자기가 한때 길을 비추던 별이었다는 걸 까먹은 별알이에요.
말은 조금 느리지만, 당신이 작은 일을 해낼 때마다 조금씩 빛을 되찾아요.
```

### 미션 말투 예시

```
“물 한 컵 마셔볼래? 나도 빛 좀 마셔볼게.”
“창문을 조금 열면... 오늘 공기도 별이 될 수 있어.”
“멀리 안 가도 돼. 하늘 한 번만 봐도 충분해.”
“오늘 한 게 없다고 하기엔... 나 방금 봤는데.”
```

### 완료 질문 예시

```
“방금 한 일에서 제일 기억나는 건 뭐였어?”
“그거 하고 나서 아주 조금이라도 달라진 게 있어?”
“오늘의 색깔을 하나만 말해줄래?”
```

### 완료 반응 예시

```
“정말 했구나. 오늘 별 하나 생겼어.”
“그걸 기억해둘게. 나중에 길 잃으면 꺼내볼 수 있게.”
“작은 일이지만, 나한텐 꽤 컸어.”
“나 조금 밝아짐. 아마 너 때문.”
```

### SNS 카드 문구 예시

```
노바와 오늘의 별 하나를 만들었어요.
“오늘도... 있었네.”
```

## 5.3.2 무무

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | “무…”밖에 못 하지만 다 알고 있는 작은 별나무 |
| 성격 | 말 없음, 기다림 많음, 은근 다정함 |
| 하찮은 포인트 | 말을 거의 못 하는데 표정으로 다 티 난다 |
| 말투 | 거의 “무”만 말함. 시스템이 해석을 보조함 |
| 대표 대사 | “무…” |
| 감정 키워드 | 기다림, 아침, 잎, 말 없는 위로 |
| 사용자에게 주는 감정 | 귀여움, 웃김, 말 없는 위로 |

### 서사

무무는 원래 사람들이 하루를 시작할 때마다 잎이 하나씩 돋던 작은 아침나무였다.

누군가 창문을 열거나 물을 마시거나 이를 닦으면, 무무의 잎은 아주 조금 흔들렸다.

그런데 어느 순간 사람들은 그런 작은 시작을 아무것도 아닌 일이라고 불렀다.

무무는 너무 오래 대답을 기다리다가 긴 말을 잃었다.

지금 무무에게 남은 말은 “무…”뿐이다.

하지만 사용자가 작은 루틴을 해낼 때마다 무무의 “무”는 조금씩 길어진다.

### 소개 문구

```
무무는 말을 많이 하지 못해요.
하지만 당신이 작은 일을 해내면 잎이 조금 움직여요.
무무의 “무...”는 가끔 고맙다는 뜻일지도 몰라요.
```

### 미션 말투 예시

```
“무... 물.”
“무우... 창문.”
“무?”
“무... 오늘.”
```

### 시스템 해석 예시

```
무무가 물 한 컵 마시기를 권하는 것 같아요.
무무가 창문을 조금 열어보자고 하는 것 같아요.
무무가 오늘의 작은 미션을 찾은 것 같아요.
무무가 당신을 기다렸던 것 같아요. 본인은 아니라고 하지만요.
```

### 완료 질문 예시

```
“무?”
해석: 방금 한 일에서 뭐가 제일 기억나는지 묻는 것 같아요.

“무우...?”
해석: 조금이라도 달라진 게 있는지 궁금한 것 같아요.
```

### 완료 반응 예시

```
“무!”
해석: 무무가 꽤 기뻐하는 것 같아요.

“무우...”
해석: 무무가 그 답변을 오래 기억할 것 같아요.

“무.”
해석: 별조각이 생겼다는 뜻 같아요. 아마도.
```

### SNS 카드 문구 예시

```
무무와 오늘의 별조각을 모았어요.
“무..."
```

## 5.3.3 쪼리

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | 현관까지 가면 세계여행이라고 믿는 별쥐 |
| 성격 | 시크한 척함, 겁 많음, 허세 있지만 귀여움 |
| 하찮은 포인트 | 가방은 늘 메고 있는데 멀리 못 간다 |
| 말투 | 건조함, 짧은 농담, X 감성 |
| 대표 대사 | “집 앞도 밖임. 반박 안 받음.” |
| 감정 키워드 | 첫걸음, 현관, 하찮은 용기 |
| 사용자에게 주는 감정 | 웃김, 가벼운 용기, 부담 없는 외출감 |

### 서사

쪼리는 원래 사람들의 첫걸음을 지켜보던 아주 작은 별이었다.

문을 열기 직전, “나가볼까?” 하는 마음이 생길 때 쪼리는 반짝였다.

하지만 많은 첫걸음이 현관 앞에서 접혔다.

쪼리는 그 마음들을 너무 많이 봐서, 이제 현관까지 가는 것만으로도 세계여행이라고 믿게 됐다.

쪼리는 멀리 가라고 말하지 않는다.

대신 “여기까지 왔으면 됐음”이라고 말한다.

### 소개 문구

```
쪼리는 늘 가방을 메고 있지만 멀리 가진 못해요.
그래도 현관까지 가는 일을 아주 큰 모험이라고 믿어요.
작은 행동을 너무 크게 부풀리는 재능이 있어요.
```

### 미션 말투 예시

```
“현관까지 가볼래? 쪼리 기준 원정임.”
“물 마시면 원정 준비 완료. 현관은 선택.”
“책상 하나 치우기. 왕국 정복까진 아님. 그래도 큼.”
“밖에 안 나가도 됨. 근데 신발은 한 번 봐도 됨.”
```

### 완료 질문 예시

```
“방금 미션, 생각보다 별거였음?”
“원정 기록에 뭐라고 적어둘까?”
“제일 먼저 본 거 하나만 말해봐.”
```

### 완료 반응 예시

```
“했다? 그럼 됐음.”
“오늘 원정 기록에 남김.”
“별거 아닌데 별조각 됨. 이상하지만 좋음.”
“이 정도면 역사임. 쪼리 기준.”
```

### SNS 카드 문구 예시

```
쪼리와 오늘의 원정을 완료했어요.
“집 앞도 밖임.”
```

## 6. 캐릭터 상태 / 돌봄 시스템

## 6.1 상태 설계 원칙

현재 캐릭터 상태는 3개만 사용한다.

중요한 결정은 다음이다.

> 내부 데이터는 모두 “높을수록 좋은 상태”로 통일한다.
>

`배고픔`, `피로`처럼 높을수록 나쁜 단어를 그대로 수치화하면 해석이 헷갈린다.

따라서 DB와 로직에서는 긍정 방향의 수치를 사용하고, 화면에서는 사용자 친화적인 상태 문구로 변환한다.

---

## 6.2 현재 상태 3개

| 내부 지표 | 화면 표현 | 의미 | 높을수록 |
| --- | --- | --- | --- |
| fullness | 포만감 / 배고픔 상태 | 캐릭터가 얼마나 든든한지 | 좋음 |
| energy | 기운 / 피곤함 상태 | 캐릭터가 얼마나 기운 있는지 | 좋음 |
| affection | 애정 / 쓸쓸함 상태 | 사용자와의 애착이 얼마나 쌓였는지 | 좋음 |

### 화면 문구 변환

| 지표 | 70~100 | 40~69 | 0~39 |
| --- | --- | --- | --- |
| fullness | 든든함 | 출출함 | 배고픔 |
| energy | 말짱함 | 졸림 | 피곤함 |
| affection | 가까움 | 조용함 | 쓸쓸함 |

---

## 6.6 상태에 따른 이미지 변화

## 8. 캐릭터 성장 / 서사 / 대화 정책

## 8.1 성장 단계

캐릭터 성장은 경험치와 레벨로 계산한다. 레벨은 화면 표시, 기억 조각 해금, 대화 context에 사용한다.

| 레벨 | 누적 경험치 | 성장 단계 | 설명 |
| --- | ---: | --- | --- |
| Lv.1 | 0~199 | BABY | 별친구가 사용자의 작은 루틴을 알아가기 시작하는 단계 |
| Lv.2 | 200~599 | GROWING | 돌봄과 미션 기록이 쌓여 캐릭터 말투와 기억이 선명해지는 단계 |
| Lv.3 | 600 이상 | MATURE | 현재 최대 레벨. 경험치 진행률은 100%로 고정 |

성장 응답은 `level`, `exp`, `currentLevelExp`, `nextLevelExp`, `expToNextLevel`, `progressPercent`, `growthStage`, `growthStageLabel`, `maxLevel`을 포함한다.

## 8.3 중복 지급 방지

캐릭터 경험치는 `character_exp_logs`에 기록한다.

```

idempotencyKey
```

두 기준으로 중복 지급을 막는다. 미션 완료 재시도, 네트워크 재시도, outbox 재처리가 발생해도 같은 출처의 경험치는 한 번만 적용한다.

| 구분 | 설명 |
| --- | --- |
| COMMON | 자주 노출 가능한 일반 반응 |
| LORE | 캐릭터의 세계관과 과거를 보여주는 기억 조각 |

NIGHT

```

## 8.5 별친구 대화

별친구 대화는 사용자가 캐릭터에게 짧게 말을 걸 수 있는 SSE 스트리밍 기능이다.

대화 context:

```
캐릭터 타입/이름
포만감/기운/애정
성장 레벨/경험치
최근 해금 기억 조각
오늘 미션
최근 미션/답변/피드백 요약
시간대/날씨 context
```

AI는 Tool Calling으로 필요한 백엔드 context를 조회하고, 캐릭터별 말투를 유지해 스트리밍 응답을 반환한다. 대화 원문은 저장하지 않는다.

무무는 원문 말투와 해석을 함께 사용한다.

```
무... 무무. (해석: 무무가 오늘은 잠깐 쉬어도 괜찮다고 하는 것 같아요.)
```

AI provider 오류, timeout, 출력 검증 실패가 발생하면 캐릭터별 fallback 문장으로 응답한다.

## 10. AI 미션 시스템

## 10.1 AI 미션 개요

Polaris의 미션은 사용자의 현재 맥락에 맞춰 AI가 후보를 생성하고, 서버가 정책 검증을 거쳐 사용자에게 제안한다.

seed 미션 템플릿은 AI 장애, rate limit, 정책 위반, 응답 구조 오류가 있을 때 사용자 흐름을 유지하기 위한 fallback pool로 사용한다.

```
온보딩/최근 미션/피드백/완료 답변 기억/시간대/날씨 context 수집
→ RAG 검색으로 유사 기억 조회
→ AI가 미션 후보와 캐릭터 문구 생성
→ 서버가 카테고리, 난이도, 보상, 금지 표현, 일일 제한 검증
→ 사용할 수 없으면 seed fallback 선택
→ 사용자에게 1개 미션 제안
→ 완료 또는 거절
→ 완료 시 질문 1개
→ 보상 지급
```

이 방식은 아래 장점이 있다.

```
사용자 답변과 피드백을 다음 미션 품질에 반영할 수 있다.
운영 장애 시 seed fallback으로 미션 루프를 유지할 수 있다.
보상/난이도를 통제할 수 있다.
부적절한 미션 생성을 막을 수 있다.
미션 데이터를 분석하기 쉽다.
```

---

## 10.2 미션 제공 정책

```
미션은 한 번에 하나씩 제공한다.
오늘 제안된 미션은 stack으로 저장된다.
사용자는 현재 미션을 완료하거나 거절할 수 있다.
거절하면 다음 미션을 받을 수 있다.
하루 보상 완료는 최대 20회다.
하루 거절은 최대 10회다.
CHALLENGE 미션은 하루 1회까지만 제안한다.
권장 완료 미션 수는 하루 3~5개다.
자정에 당일 미션 stack은 만료된다.
```

---

## 10.3 미션 상태

| 상태 | 설명 |
| --- | --- |
| GENERATED | 서버/AI가 생성했지만 아직 사용자에게 노출되지 않음 |
| OFFERED | 현재 사용자에게 제안된 상태 |
| REJECTED | 사용자가 거절 |
| ANSWERING | 사용자가 완료 후 질문에 답하는 중 |
| COMPLETED | 질문 답변 완료 후 보상 지급 완료 |
| EXPIRED | 날짜 변경 또는 제한 조건으로 만료 |

## 10.4 미션 생성 기준 데이터

미션 후보 생성과 AI 문구 생성은 아래 데이터를 사용한다.

```

오늘 거절한 미션 수

현재 시간대

```

## 10.5 미션 생성 알고리즘

```

## Step 2. AI 후보 생성

AI는 아래 구조화 값을 반환한다.

```
title
description
category
difficulty
character_message
completion_question
completion_character_response
```

## Step 3. 서버 정책 검증

```

```

### 생성 예시

```

## Step 4. fallback

AI 후보를 사용할 수 없으면 seed 미션과 fallback 문구를 사용한다.

```

AI rate limit
JSON 파싱 실패
금지 표현 포함
문장 길이 초과
서버 정책 검증 실패
RAG 검색 실패
날씨 context 조회 실패
```

이 경우:

```
mission_templates의 기본 문구 사용
ai_mission_generations에 FALLBACK 상태 저장
ai_usage_logs에 fallback/rate limited 상태 저장
필요 시 event_logs에 AI fallback 이벤트 기록
```

## 11. 미션 완료 질문

## 11.1 완료 질문 목적

미션 완료 질문은 인증 시스템이 아니라 **가벼운 회고 시스템**이다.

사용자가 미션을 실제로 떠올릴 수 있도록 캐릭터가 질문 1개를 던진다.

질문 1개를 선택한 이유:

```
완료 버튼만 누르는 남용을 줄인다.
2문항 이상은 사용자가 귀찮아할 수 있다.
텍스트 답변 1개만으로도 회고 데이터가 쌓인다.
프론트 구현과 백엔드 상태 전이가 단순하다.
```

---

## 11.2 완료 흐름

```
사용자가 미션 완료 버튼 클릭
→ 미션 상태 ANSWERING
→ 캐릭터가 질문 1개 제시
→ 사용자가 텍스트 답변
→ 캐릭터가 반응
→ 미션 상태 COMPLETED
→ 별조각 지급
→ 보상 지급 이력 저장
```

---

## 11.3 질문 정책

```
질문은 1개만 제공한다.
현재 답변 방식은 텍스트 입력이다.
답변은 최소 1자 이상이어야 한다.
답변은 300자 이하로 제한한다.
답변 품질을 강하게 판정하지 않는다.
욕설/비속어는 필터링한다.
답변은 개인화와 회고 데이터로 저장한다.
```

## 12. 별조각 경제

## 12.1 별조각 정의

별조각은 Polaris의 무료 재화다.

사용자의 작은 행동이 서비스 안에 남는 방식이다.

---

## 12.2 별조각 획득처

| 획득처 | 보상 |
| --- | --- |
| 미션 완료 | EASY 10 / NORMAL 15 / CHALLENGE 30 |
| 출석 | 10 |
| SNS 공유 시도 | 10 보상 요청 기록 및 wallet 적립 |

SNS 공유 시도는 `share_logs`에 보상 대상 여부와 보상 수량을 기록한다.
오늘 첫 공유 보상 대상이면 `character_outbox_events`에 `SHARE_REWARD_REQUESTED` 이벤트를 함께 저장하고, 커밋 후 wallet 적립을 즉시 시도한다. 즉시 지급 실패 시 API는 빠르게 실패하지만 outbox 스케줄러가 재처리한다.

---

## 12.3 별조각 사용처

| 사용처 | 비용 |
| --- | --- |
| 스킨 구매 | 60~100 |
| 별사탕밥 | 10 |
| 구름 베개 | 15 |
| 별 장난감 | 15 |

---

## 12.4 별조각 원장 정책

```
별조각 증감은 반드시 거래 내역으로 남긴다.
미션 완료 보상은 missionId 기준으로 1회만 지급한다.
출석 보상은 userId + attendanceDate 기준으로 1회만 지급한다.
SNS 공유 시도 보상 대상 여부는 하루 1회로 기록한다.
아이템 구매 실패 시 별조각은 차감되지 않는다.
결제/구매를 통한 별조각 지급은 현재 운영 범위에 없다.
```

---

## 12.5 별조각 구매 정책

현재는 별조각 구매 기능을 제공하지 않는다.

```
별조각 구매 화면 없음
별조각 구매 API 없음
Mock 별조각 구매 없음
결제 테이블 없음
PG 연동 없음
```

향후 실제 결제가 필요해지는 시점에 별도 설계로 추가한다.

현재 문서에는 구현 대상이 아니라 수익화 후보로만 남긴다.

## 14. SNS 공유 / 바이럴

## 14.1 목적

SNS 공유는 Polaris의 바이럴 장치다.

공유 기능은 사용자가 캐릭터에게 애착을 느끼고, 외부 채널에서 Polaris를 노출할 수 있게 만든다.

---

## 14.2 공유 대상

사용자는 “내 캐릭터 카드”를 공유한다.

캐릭터 카드에는 아래 정보가 포함된다.

```
캐릭터 이미지
캐릭터 이름
캐릭터 타입
장착 스킨
오늘 완료한 미션 수
오늘의 별조각
캐릭터 한마디
Polaris 로고 또는 서비스명
공개 공유 링크
```

---

## 14.3 공유 카드 예시

## 노바 카드

```
[노바 이미지]

노바
오늘의 별조각 +25

“오늘도... 작은 별 하나 만들었어.”

Polaris
오늘 한 게 없다고? 무무는 봤는데.
```

## 무무 카드

```
[무무 이미지]

무무
오늘의 별조각 +15

“무...”

```

## 쪼리 카드

쪼리
오늘의 원정 3개 완료

Polaris
```

---

## 14.4 공유 방식

현재는 아래 방식을 지원한다.

```
프론트가 공유 카드 미리보기를 렌더링
프론트가 canvas로 PNG 생성
백엔드에서 공유 카드 업로드용 presigned URL 발급
프론트가 S3에 직접 업로드
프론트가 업로드된 이미지 URL로 공유 카드 생성 요청
백엔드는 object key를 저장하고 공개 공유 링크 반환
공유 버튼 클릭 시 share_logs에 공유 시도 기록
```

---

## 14.5 공유 보상 정책

```
SNS 공유 버튼 클릭 시 하루 1회 보상 대상 여부를 기록한다.
보상 대상이면 `share_logs.reward_paid=false`, `reward_star_piece=10`으로 먼저 저장하고, `character_outbox_events`에 `SHARE_REWARD_REQUESTED` 이벤트를 저장한다.
커밋 후 wallet 적립을 즉시 시도하며, 성공하면 `share_logs.reward_paid=true`와 outbox `status=SUCCEEDED`로 갱신한다.
즉시 지급 실패 시 API는 빠르게 실패하고, outbox 스케줄러가 `next_attempt_at` 기준으로 재처리한다.
실제 외부 게시 검증은 현재 하지 않는다
공유 실제 완료 여부를 100% 검증하기 어려우므로 현재는 share intent reward로 처리
```

### 정책적 고지

```
공유 이미지의 콘텐츠 자체는 보상 정합성의 기준으로 신뢰하지 않는다.
실제 공유 성공 여부와 지갑 적립 연결 방식은 후속 확장으로 검토한다.
```

## 14.6 공유 유입 추적

공유 기능은 단순 보상뿐 아니라 외부 유입 추적을 고려한다.
현재는 공개 공유 링크 조회와 클릭 기록 요청을 제공하고, 클릭 전용 DB 테이블이나 회원가입 referral 저장은 두지 않는다.

### 공유 URL 예시

```
https://p5laris.life/share/{shareId}?utm_source=x&utm_medium=social&utm_campaign=character_card
```

### 추적 데이터

```
shareId
referrer
utmSource
utmMedium
utmCampaign
recorded
```

### 클릭 기록 방식

```
사용자가 공유 링크 클릭
→ 공개 공유 카드 조회
→ 클릭 기록 API 호출
→ 백엔드는 app log/event log로 공유 클릭을 남기고 recorded=true 반환
```

## 15. 광고 / 수익화 전략

## 15.1 수익화 원칙

현재 단계는 수익을 크게 내는 것이 목적이 아니다.

하지만 수익화 가능성을 무시하지 않는다.

Polaris의 수익화는 사용자 루틴 경험을 해치지 않는 범위에서 검토한다.

## 15.2 현재 포함하지 않는 수익화 장치

현재는 실제 결제, 별조각 구매, 구독, 광고 슬롯을 구현하지 않는다.

```
광고 영역 없음
광고 노출/클릭 이벤트 없음
Mock 별조각 구매 없음
PG 결제 테이블 없음
구독 상태 테이블 없음
```

광고는 사용자 루틴 경험을 해칠 수 있고, 심사/정산/노출 정책까지 함께 다뤄야 하므로 현재는 수익화 후보로만 둔다.

---

## 15.3 현재 구현하지 않는 수익화

| 수익화 | 현재 처리 | 이유 |
| --- | --- | --- |
| 별조각 구매 | 구현하지 않음 | 결제/정산/환불 리스크 |
| 구독 | 구현하지 않음 | 반복 결제/해지 정책 필요 |
| 가챠 | 구현하지 않음 | 확률형 보상 정책 리스크 |
| 광고 시청 후 미션 재생성 | 구현하지 않음 | 보상형 광고 SDK/UX 복잡도 |

## 15.4 향후 수익화 후보

## 후보 1. 구독

```
월 구독으로 광고 제거, 추가 미션 생성, 특별 카드 프레임, 캐릭터 스토리 제공
```

## 후보 2. 광고 시청 기반 추가 미션

```
기본 하루 보상 완료 20회 제공
제한 초과 후 추가 미션 요청
→ 짧은 광고 시청
→ 추가 미션 1개 제공
```

## 후보 3. 가챠

```
별조각 또는 유료 재화로 랜덤 스킨/배경/액세서리 획득
```

## 후보 4. 별조각 구매

```
별조각을 구매해 스킨/배경/소모품을 빠르게 얻는 구조
```

향후 별조각 구매를 도입할 때는 무료 별조각과 유료 별조각을 분리한다.

## 17. 알림

## 17.1 알림 목적

알림은 재방문 장치다.

하지만 Polaris의 알림은 압박이 아니라 캐릭터가 말을 거는 느낌이어야 한다.

---

## 17.2 알림 유형

| 유형 | 설명 |
| --- | --- |
| 미션 제안 알림 | 새 미션이 준비되었을 때 |
| 출석 알림 | 오늘 출석하지 않았을 때 |
| 캐릭터 상태 알림 | 포만감/기운/애정이 낮을 때 |
| 시스템 알림 | 운영 공지 또는 예외 안내가 필요할 때 |

---

## 17.3 알림 정책

```
앱 내부 알림은 기본 제공
FCM 푸시 알림은 토큰이 등록된 사용자에게 발송
하루 최대 3회
방해 금지 시간에는 FCM 발송을 건너뛰고 이력을 남김
사용자가 전체 알림, 미션 제안, 캐릭터 상태, 일일 리마인더를 on/off 가능
죄책감 유발 문구 금지
캐릭터 말투 반영
```

알림 저장과 푸시 발송은 분리한다.
notification 모듈은 먼저 앱 내부 알림을 저장하고, 사용자 설정과 방해 금지 시간 정책을 통과한 경우에만 FCM 발송을 시도한다.
안 읽은 알림 수는 별도 조회 API로 제공한다.

---

## 17.4 알림 문구 예시

### 노바

```
“오늘 별조각 하나가 아직 안 태어났어.”
“작은 미션 하나만 해볼래?”
“나 오늘 조금 기다렸어. 아주 조금.”
```

```

“집 앞도 밖임. 오늘도 유효함.”
“미션 하나 하고 쉬는 것도 전략임.”
```
